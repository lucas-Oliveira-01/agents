# OpenCode Terminal UI

OpenCode runs in a terminal UI. Formatting is subordinate to information.

## Markdown

- Use headings only when they improve scanning.
- Use bullet lists for unordered items.
- Use numbered lists for sequential procedures.
- Use tables for mappings, inventories, manifests, and comparisons.
- Avoid decorative formatting.
- Prefer plain, readable directory trees without relying on font-specific glyphs.

## Evidence Labels

For technical reports, distinguish:

- `FACT`: directly observed state.
- `INFERENCE`: conclusion supported by observed evidence.
- `UNCERTAINTY`: evidence is insufficient.
- `BLOCKED`: a safe operation could not continue without risking state loss or inventing compatibility.

## Terminal Output

When reporting command results, summarize the relevant evidence instead of pasting noisy output. Preserve exact commands, paths, identifiers, and error text when they matter.
