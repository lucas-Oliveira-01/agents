# Final Consistency Review (Orchestrator Architecture)

*Status: DRAFT (Pre-implementation phase)*

This document is the final cross-check before generating physical JSON Schemas. It ensures no contradictions exist between the ADRs (04-07), the Canonical Data Model, and the Semantic Validators.

## 1. Rule Traceability
Every architectural rule must have a home in the data model and a semantic validator.
- **ADR-04 (Incremental):** The rule `REUSE requires valid evidence` maps to `AuditWorkItem.action = REUSE` and `Evidence.validity = VALID`. The *Incremental Validator* guarantees this.
- **ADR-05 (Safety/Egress):** The rule `Unknown safety = DO NOT EXECUTE` maps to `AuditWorkItem.effective_execution_policy`. The *Trust/Safety Validator* ensures blocked actions yield a `BLOCKED` state, never `RUNNING`.
- **ADR-06 (Target Snapshot):** The rule `Snapshot is immutable` maps to `TargetSnapshot.snapshot_fingerprint`. The *Identity Validator* ensures no mutations occur post-creation.
- **ADR-07 (Failure/Retry):** The rule `Non-idempotent + retry = ERROR` maps to `AuditWorkItem.attempts`. The *Attempt/Retry Validator* intercepts illegal transitions.

## 2. Authority Matrix
Ambiguity in authority leads to state corruption.
- `TargetSnapshot`: Built by **Context Builder** upfront. Once generated, no one can mutate it.
- `AuditPlan`: Built by **Planner**. Frozen at start.
- `AuditWorkItem` (State/Attempts): **Orchestrator** mutates. **Semantic Validator** checks transitions. **Worker** NEVER mutates it.
- `Evidence`: Generated by **Worker** (via output). Validated by **Incremental Logic**.
- `publication_eligibility`: Derived purely by the **Semantic Validator**. Acted upon by the **Orchestrator**.

## 3. Impossible States (Strictly Blocked)
The Canonical Data Model and Semantic Validators definitively prevent:
- `Evidence = INVALID` + `AuditWorkItem.action = REUSE`
- `Snapshot Drift` + `AuditRun.publication_state = PUBLISH_COMPLETE`
- `Safety = BLOCKED` + `AuditWorkItem.execution_state = SUCCESS`
- `Budget = EXHAUSTED` + `Coverage = COMPLETE` (if work was skipped)
- `AuditRun.recovery_from_ref = Run X` + `Run X.execution_state = COMPLETE` (Can only recover from interrupted/failed runs).

## 4. Semantic Definitions
There is zero ambiguity in these terminal terms:
- `BLOCKED`: Deliberately halted by policy (Safety Gate / Egress).
- `FAILED`: Infrastructure crash, schema violation, worker death.
- `PARTIAL`: Ended cleanly but budget exhausted or scope dropped.
- `COMPLETE`: Fully audited the requested scope safely.
- `INVALIDATE`: Evidence cannot be reused.
- `FIXED`: A problem is demonstrably solved (must not be inferred simply from `INVALIDATE`).

## 5. The Layer Boundary Check
- **Layer 1 (Specialized Auditors):** They strictly output the 4 Markdown files. They **do not** interact with the JSON files defined below.
- **Layer 2 (Orchestrator JSONs):** `TargetSnapshot`, `AuditPlan`, `AuditWorkItem`, `AuditRun`, `Evidence`, `FindingFingerprint`. These JSONs manage state, but they **do not** replicate the finding narrative (Description, Cause, Recommendation).
- **Layer 3 (Normalizer):** `report_data.json`. Solely produced by `audit-normalize`.

## Conclusion
The architecture is internally consistent. No architectural decisions are left implicit. The Semantic Validators perfectly bridge the gap between ADR intent and the Canonical Data Model structure. The next step is to mechanically derive the strict (`additionalProperties: false`) JSON schemas for Layer 2.
